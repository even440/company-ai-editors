# 多维表格（base）

入口 `apps/editors/base/main.tsx`，组件在这个目录：`BaseEditor.tsx`（状态、数据表页签、工具栏、视图页签、筛选条、宿主消息、导入）、`GridView.tsx`（表格视图，列模型用 `@tanstack/react-table` 9，行按滚动位置只画可见的一段）、`views.tsx`（看板、画廊、日历、表单）、`modals.tsx`（记录、字段、视图、数据表、导入结果弹窗）、`cells.tsx`（格子的显示和编辑控件、弹出面板、附件、签字板、扫码）、`model.ts`（一张表的内容模型和筛选 / 排序 / 纯文本 / 一句话筛选 / 汇总）、`book.ts`（几张数据表、关联、查找引用、重算）、`formula.ts`（公式）、`lark.ts`（导入 Lark / 飞书的 .base）、`export.ts`（导出 Excel）、`i18n.ts`（界面文字）。`model.ts`、`book.ts`、`formula.ts`、`lark.ts` 不碰 DOM。界面照原型 `prototype-v2/views-docs2.js` 的 `CAI.docEditors.base`。

2026-11-10 用户拿 Lark 导出的货柜表对照（「work 的多维表格很简单」），又发了 Lark 的字段类型清单（「这些都需要支持」）：字段类型从 8 种加到 29 种，一份多维表格能放几张数据表，筛选能有几个条件，能导入 Lark 的导出文件。

## 内容格式

```jsonc
{
  // 第一张数据表在最外层（2026-11-10 以前的内容原样就是「只有一张表」；平台的 AI 加记录、取纯文本也只认这三样）
  "tid": "t1", "name": "货柜",
  "fields": [
    { "id": "f1", "name": "清单编号", "type": "text" },
    { "id": "f2", "name": "进度", "type": "stage", "opts": [["装柜", "gray"], ["已签收", "green"]] },
    { "id": "f3", "name": "清关费", "type": "currency", "cur": "BRL", "dec": 2 },
    { "id": "f4", "name": "含税", "type": "formula", "expr": "ROUND({清关费} * 1.12, 2)", "dec": 2 },
    { "id": "f5", "name": "清关行", "type": "duplex", "to": "t2", "back": "g4" },
    { "id": "f6", "name": "清关行电话", "type": "lookup", "via": "f5", "pick": "g2" }
  ],
  "records": [
    { "id": "r1", "v": { "f1": "HG-1001", "f2": "装柜", "f3": 25600, "f4": 28672, "f5": ["c1"], "f6": "+55 13 3333-1000" }, "ct": 1794245578000, "ut": 1794245826000, "cb": "ln", "ub": "wl" }
  ],
  "views": [
    { "id": "v1", "name": "未签收", "type": "grid", "filters": [{ "fid": "f2", "op": "ne", "val": "已签收" }, { "fid": "f3", "op": "nempty", "val": "" }], "sort": { "fid": "f1", "dir": "asc" }, "hidden": ["f6"] },
    { "id": "v2", "name": "按进度", "type": "kanban", "group": "f2" }
  ],
  // 第二张起的数据表
  "tables": [{ "id": "t2", "name": "清关行", "fields": [ /* … */ ], "records": [ /* … */ ], "views": [ /* … */ ] }]
}
```

### 字段类型和值

分三组，和 Lark 的清单一样（`model.ts` 的 `TYPE_GROUPS`）。空值是 `""`（复选框是 `false`，值是一组的是 `[]`）。

| 类型 | 值 | 字段上的设置 |
|---|---|---|
| `text` 文本、`phone` 电话、`email` 邮箱、`url` 链接 | 字符串。电话、邮箱、链接显示成能点的 | |
| `barcode` 条码 | 字符串，用等宽字。能用摄像头的地方有「扫码」：浏览器自己会认条码的（`BarcodeDetector`，Chrome 在 Mac、安卓上有）用它，没有的（iPhone、Windows）用 `@zxing/library`（点了扫码才加载）；也可以手输或用扫码枪 | `scan: true` 只能扫码录入（照 Lark 的「仅限扫码录入」）：输入框只读，表格里点格子直接开摄像头 |
| `number` 数字、`currency` 货币、`progress` 进度、`rating` 评分 | 数字。进度是 0–100，评分是 1–5 | `dec` 小数位数（不设照填的显示，货币默认 2）；货币 `cur` 币种代码 |
| `select` 单选、`stage` 流程、`multi` 多选 | 选项名；多选是选项名数组。流程的选项有先后，格子里标「第几步 / 共几步」，记录弹窗里是一排步骤 | `opts`：`[名称, 颜色]`，颜色是 base.css 里 `.c-*` 的名字（blue / green / orange / purple / teal / red / yellow / gray）；流程另有 `flow`（见下面「流程」） |
| `check` 复选框 | 布尔 | |
| `date` 日期 | `YYYY-MM-DD`；带时间的是 `YYYY-MM-DD HH:mm` | `time: true` 带时间 |
| `user` 人员 | 成员编号（`s.client.directory()`） | |
| `group` 群组 | 会话编号数组。群名单来自 `s.client.groups()`（宿主没有这个接口时一个都没有）：`mine` 的是当前成员在的群，能选、点了发 `open-chat` 让宿主打开；这份内容里已经填着、自己不在的群宿主也给名字（`mine: false`），所以谁看都是群名，只是点不开 | |
| `attach` 附件 | `[{ id, name, size, mime, url }]`（`s.client.upload` 的结果）。显示、下载一律用 `s.client.assetUrl(id)` 现拼地址，不用存着的 `url` | |
| `sign` 签字 | 一个文件 `{ id, name, size, mime, url, by, at }`：在画板上写，存成白底 PNG 上传；`by` / `at` 是谁签的、什么时候 | |
| `location` 地理位置 | 地址文字；点过「用当前位置」的是 `{ addr, lat, lng }`。显示成打开地图的链接 | |
| `link` 单向关联、`duplex` 双向关联 | 对方数据表里的记录编号数组；显示对方记录的标题（第一个文本字段） | `to` 对方的数据表（可以是本表）；双向的 `back` 是对方表里成对的字段，这边改了对方那边跟着变（`book.ts` 的 `setLink`） |
| `lookup` 查找引用 | 算出来的：到另一张数据表里找出一些记录，把它们某个字段的值列出来或汇总。找法两种：**按条件**（照 Lark，新建的默认）——`from` 是对方的数据表（可以是本表，不算这条记录自己），`where` 是查找条件 `{ fid 对方的字段, op, src 本表的字段 \| val 固定值 }`，要同时满足，这边拿去比的值是空的就什么都找不到；或者**顺着本表的关联字段** `via` | `pick` 取对方的哪个字段；`agg`：不写是列出来，`uniq` 去掉重复的列出来，`sum` / `avg` / `min` / `max`，`count` 数有几条，`ucount` 数有几种 |
| `formula` 公式 | 算出来的：数字、文字或真假；算不出是 `"#ERROR"` | `expr` 式子（见下面「公式」）、`dec` |
| `button` 按钮 | 没有值。点了依次做 `acts` 里的几件事（见下面「按钮」） | `label`、`acts` |
| `autonum` 自动编号 | 数字，新记录取字段的 `next` 再加一；字段刚变成自动编号时已有的记录从 1 编起 | `next` |
| `created` 创建时间、`updated` 修改时间、`creator` 创建人、`editor` 修改人 | 不在 `v` 里，读记录上的 `ct` / `ut`（毫秒）、`cb` / `ub`（成员编号）。2026-11-10 以前的记录没有，显示为空 | |

- 系统填、系统算的（`isAuto`：自动编号、四个创建 / 修改字段、公式、查找引用）不能手改，表单视图里不出现；按钮也不进表单和导出。
- **重算**（`book.ts` 的 `recompute`）：内容每次变了都过一遍——清掉指向已删记录的关联，算公式和查找引用，结果写进记录的 `v`（所以平台取到的纯文本、导出、筛选排序都直接有值）。没变的表和记录还是原来的对象。平台的 AI 加的记录要到下次在编辑器里改动时才算上公式。
- **公式**（`formula.ts`）：`{字段名}` 引用本表的字段（字段改名时本表的公式跟着改）；`+ - * / ^`、`&` 连接、比较；日期能直接加减（日期 − 日期是天数）；函数 IF、IFS、IFERROR、IFBLANK、AND、OR、NOT、ISBLANK、SUM、AVERAGE、MIN、MAX、COUNTA、ROUND、ROUNDUP、ROUNDDOWN、INT、ABS、MOD、POWER、SQRT、LEN、LEFT、RIGHT、MID、UPPER、LOWER、TRIM、CONCATENATE、TEXT、VALUE、CONTAIN、FIND、SUBSTITUTE、TODAY、NOW、DATE、YEAR、MONTH、DAY、HOUR、MINUTE、WEEKDAY、DAYS、DATEDIF、RECORD_ID。中文的括号、逗号、引号也认。不能引用别的数据表（用查找引用把值取过来再算）。
- **流程**（照 Lark 的流程字段；`model.ts` 的 `stageBlock`）：`flow: { strict, first, steps: { 选项名: { show, need, end } } }`。`first` 新记录从第一个阶段开始；`steps` 里每个阶段：`show` 是这个阶段要处理的字段（记录弹窗里标一个点），`need` 是流转条件（和视图的筛选条件一个写法，界面上是「填了这些才能进入下一个阶段」，也就是 `nempty`；导入来的别的条件原样留着、照样算），`end` 是 `done` 完成或 `stop` 中止。规矩：往回退、清空、进入中止的阶段（暂停、取消）随时可以，从中止的阶段回到哪一步都行；往前走时路过的每个阶段的流转条件都要满足，`strict` 时还只能进下一个阶段。在表格里选、看板里拖、记录弹窗里点、按钮里「换成下一个选项」都过这一关，不行就提示还差什么。没设过 `strict`、流转条件、结束阶段的流程字段就是一个有先后的单选。
- **按钮**（照 Lark 的「点击按钮时」自动化；`book.ts` 的 `runButton`）：`acts` 从上到下依次做——`{ do: 'set', set }` 修改这条记录，`{ do: 'add', table, set }` 在某张数据表里新增一条记录，`{ do: 'msg', users, groups, fields, text }` 发消息（`fields` 是这条记录里的人员 / 群组字段，`text` 里的 `{字段名}` 换成这条记录改完以后的值；交给宿主的 `POST …/notify` 去发），`{ do: 'open', href }` 打开地址（只让打开 http(s)、mailto、tel）。`set` 的每一项 `{ fid, how, val?, from? }`：`val` 固定值、`now` 当时的日期时间、`me` 点按钮的人、`next` 单选 / 流程的下一个选项、`copy` 照抄这条记录的 `from` 字段、`this` 关联这条记录（新增到别的表时给指回来的关联字段）、`clear` 清空；系统填的、算出来的、附件和签字不能由按钮填。流程被流转条件挡住时整个按钮不做。只读时只有全是「打开地址」的按钮能点。2026-11-10 当天早先的 `href`（只能打开地址）读的时候挪进 `acts`。Lark 里按记录变化、按时间触发的自动化这边还没有。
- 换类型时值尽量转换（`model.ts` 的 `coerce`），转不了的清空；关联只在单向 ↔ 双向之间带得过去，建好以后不能换表。删掉数据表、删掉关联字段时，指着它的关联和查找引用变成文本、留下当时的字。

### 视图

- 视图类型 `grid | kanban | gallery | calendar | form`。`group` 在看板里是分组用的单选或流程字段，在日历里是排列用的日期字段；`sort.dir` 是 `asc | desc`；`hidden` 是这个视图里隐藏的字段编号。筛选、排序、隐藏都存在视图里，切回来还在。
- `filters` 是筛选条件的数组，要同时满足（2026-11-10 以前只有一个条件、存在 `filter` 里，读的时候挪进来）。每个条件 `{ fid, op, val, vals? }`：`op` 是 `has` 包含 / `nhas` 不包含 / `eq` 等于 / `ne` 不等于 / `gt` 大于 / `lt` 小于 / `empty` 为空 / `nempty` 不为空；单选、多选、流程字段在筛选条里是勾选项，勾了几个存在 `vals`（「等于」「包含」对上任意一个就算，「不等于」「不包含」要都对不上），`val` 总是第一个。
- 大于、小于：两边都是数字按大小比，别的按显示的文字比（日期刚好可比）。以前两边都先 `parseFloat`，「2026-10-31」读成 2026，同一年的日期比不出先后，2026-11-10 改掉。
- 画廊的封面是记录的附件里第一张图片，没有图片是按单选颜色的色块。

### 其他

- `content` 为 `{}` 时初始化：名称（text）、状态（select）、负责人（user）、截止日期（date）四个字段，没有记录，一个表格视图和一个按「状态」分组的看板。
- `plain`：每条记录一行，`字段名: 值` 用空格连起来（人员显示姓名，复选框显示是 / 否，多选用「、」连，关联是对方记录的标题，附件是文件名）；几张数据表时每张前面一行 `【表名】`。

## 导入 Lark / 飞书的 .base

`s.doc.importFile` 是 `.base`（Lark 多维表格「导出 → 多维表格文件」）时，打开就转换、保存、`imported()`，再弹出导入结果（带过来多少、哪些没法原样带过来）。文件格式没有公开说明，`lark.ts` 开头写了读到的结构；示例 `tools/samples/sample.base` 是照真实文件的结构造的（假宿主的 `demo-base-import`）。

- 文件里的几张表一起导入成几张数据表，表之间的关联接上（对方那张表也在文件里才行）。
- 类型对应：文本 / 条码 / Email、数字 / 货币 / 进度（0–1 换成百分数）/ 评分、单选、流程（每个阶段要处理的字段、流转条件、完成和中止的阶段、只能进下一阶段、新记录从第一阶段开始都带过来）、多选、日期（按表格的时区读，带不带时间看 `timeFormat`）、复选框、电话、超链接、地理位置、单向 / 双向关联、公式（引用换成 `{字段名}`，按这边的写法重算）、创建时间、最后更新时间、自动编号（纯数字的接着编，带前缀的改成文本）、按钮（留着字段，点了做什么要重新设）、附件（导出文件里没有文件本身，字段留着）。人员、创建人、修改人、群组、查找引用对不上这边的数据，按文本留下名字。
- 视图：表格、看板、画廊、表单；隐藏的字段、第一个排序、筛选条件（「同时满足」的都带过来，「满足任一」的不带）。表格视图里的分组、列宽、冻结列、条件颜色，以及权限角色、自动化、仪表盘不导入。

## 宿主消息

| 消息 | 处理 |
|---|---|
| `export`，`format: 'xlsx'` | 导出当前数据表、当前视图看得见的记录和字段（已筛选、已排序、未隐藏；按钮不导出，数字类写成数字），一个工作表，文件名是标题 |
| `command` `filter`，`args` 是一句话 | 按原型 `CAI.baseNlq` 的规则解析成筛选条件并应用到当前视图（表单视图会先切到第一个列表视图）：「大于 / 超过 30」「小于 / 不到 30」用数字字段，「10 月 20 日之后」用日期字段，「负责人是李娜」或句子里出现通讯录里的名字用人员字段，出现某个选项名用那个单选 / 多选字段，「已续约的」用复选框字段，其余取句子里第一个像样的词在第一个文本字段里找包含。句子里提到了字段名就用那个字段，否则用第一个同类型的字段。解析不出就提示 |
| `command` `summary` | 统计当前视图的记录：条数、数字字段的合计 / 平均 / 最大 / 最小、单选 / 人员 / 多选的分布、复选框的勾选数、日期范围；通过 `{ type: 'selection', text }` 发回宿主 |
| `command` `addFields`，`args` 是 `[{ name, type, opts? }]` | 往当前数据表追加字段；`opts` 可以是名称数组或 `[名称, 颜色]` 数组，单选 / 多选 / 流程没给选项时放两个占位选项。关联、查找引用、公式要选表、写式子，这里不收（按文本加） |
| `insert`，`text` 或 `html` | 在当前数据表新增一条记录，文字放进第一个文本字段 |
| `readonly` | 切换只读：不能改格子、字段、记录和视图，但还能切视图、筛选、排序、隐藏字段（这些改动不保存） |
| `title` | 更新表单视图顶部显示的标题 |
| `flush` | 立刻保存（会话本身也会处理） |

编辑器发给宿主的：点了群组字段里自己在的群发 `{ type: 'open-chat', convId }`；按钮「发消息」调 `POST {api}/api/v1/editor/notify { users, groups, text }`（宿主以当前成员的名义发，返回发到了几处）。

## 界面

- 数据表页签（最上面一行）：点击切换；点当前页签（或右键）重命名 / 删除；「+ 数据表」新建。只有一张表又是只读时不显示这一行。
- 视图页签：点击切换；点当前页签（或右键任一页签）打开重命名 / 删除；「+ 视图」新建（名称 + 类型）。
- 工具栏：筛选（筛选条：一行一个条件，字段 / 条件 / 值，「添加条件」加一行）、排序（字段 + 升降序）、分组（看板）、字段（显示 / 隐藏、编辑、删除、添加）、新增记录、记录数。
- 表格：格子点一下就改（文本、数字这类是输入框，单选 / 流程 / 多选 / 人员 / 关联 / 群组弹出勾选面板，复选框直接切换，评分直接点星星，附件弹出文件列表和上传，签字打开这条记录的弹窗去签，按钮直接点）；系统填、系统算的格子不能改；列头点击或右键打开菜单（编辑字段、左右插入、升降序、按它筛选、隐藏、删除）；行号点开记录弹窗；表尾「+ 新增记录」。
- 字段弹窗（`modals.tsx` 的 `FieldModal`）：单选 / 多选的选项一行一个（2026-10-29 以前是逗号隔开的一个输入框），回车在下面加一行、空行按退格删掉，底下「添加选项」；粘贴用逗号、顿号或换行隔开的一串拆成几行；已有的选项留着原来的颜色，新加的接着配色；一样的名字只留第一个，都不填就从已有的值里收集。
- 字段弹窗的「类型」分常规 / 业务 / 高级三组；按类型多出各自的设置：日期的「包含时间」、数字类的小数位数、货币的币种、关联的对方数据表、查找引用的关联字段 / 取哪个字段 / 怎么汇总、公式（点字段名、函数名插进去，写错了当场提示）、按钮的文字和地址。
- 看板：按单选或流程字段分组，卡片可拖到别的列；画廊：卡片；日历：按日期字段排月历，可切换月份，双击某天新增那天的记录；表单：填写后成为一条新记录并回到表格视图。
- 手机宽度：页签、表格、看板都能横向滚动，工具栏只留图标。
